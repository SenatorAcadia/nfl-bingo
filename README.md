# NFL BEANO

Version 24.1.0 is a staged game-night release. It preserves the existing browser interface while replacing the public MQTT room with an authenticated WebSocket service and deliberately temporary in-memory rooms.

## 1. Current scope

- One host creates a four-character room and selects an NFL game.
- Friends join with the room code; no user account is required.
- The host token is generated by the server and kept in that browser session.
- Room state stays in server memory for this week; no database or user account is required.
- Cards contain 16 common, 6 uncommon, and 2 rare events.
- The host can call or revoke an event if the feed misses or misclassifies a play.
- Rerolls close after the first official event.
- The client processes every unseen play, polls every four seconds, and shows visible feed health.
- If the in-memory service restarts while the host page remains open, the host automatically recreates the room and players reconnect.

The ESPN adapter remains temporary while a licensed live provider is evaluated. Do not treat it as a supported production API.

## 2. Local development

Requirements:

- Node.js 22.5 or newer
- npm

```powershell
npm ci
npm test
npm start
```

Open `http://127.0.0.1:8080`. The health endpoint is `http://127.0.0.1:8080/health`.

## 3. Docker deployment

Build and run the service locally on the server:

```bash
docker compose up -d --build
docker compose ps
curl --fail http://127.0.0.1:8080/health
```

The Compose port is bound to `127.0.0.1` intentionally. Put nginx or another TLS reverse proxy in front of it and proxy both HTTP and WebSocket upgrades.

Rooms normally reset whenever the application container restarts. The open host page can recreate its active room automatically, but a deliberate deployment should still happen between games.

## 4. Reverse-proxy requirements

The public proxy must provide HTTPS and forward these headers:

- `Host`
- `X-Forwarded-For`
- `X-Forwarded-Proto`
- WebSocket `Upgrade`
- WebSocket `Connection`

See `deploy/nginx.conf.example` for a location block that can be incorporated into an existing HTTPS virtual host.

## 5. Verification

```bash
npm test
docker compose config
docker compose build
docker compose up -d
curl --fail http://127.0.0.1:8080/health
```

Then open two private browser windows, host a replay game in one, join from the other, and verify that all selected cards, feed calls, manual corrections, and wins remain synchronized.

## 6. Known boundary

User accounts and durable storage are intentionally not part of 24.1.0. A host token prevents ordinary players from sending host-only messages, while room codes provide friend access. Accounts can be reconsidered after opening week.
